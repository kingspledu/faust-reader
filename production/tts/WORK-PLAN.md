# 제1부 문장별 TTS 제작 계획

## 1장 진행 결과 · 2026-11-23

사용자가 승인한 초안을 기준으로 나레이션 57문장·시인 독백 3문장을 검토했다. 문단 복원·고유 ID·대본/색인·DSP·모의 일괄 생성 검사를 통과했다. 실제 Chrome에서 코드 복사 문자열 일치,404·해시 불일치 거부,복사 차단 시 수동 선택을 확인했다. 단일 장이라 빠른 복수 장 전환은 해당 없음이다. `/tts/`에 배포할 1장 문장별 HTML과 코드 복사 페이지를 준비했다. 실제 Canvas 음성 생성·다운로드·청취는 아직 미검증이다. 아래 전편 체크리스트는 28장 전체 완료를 뜻하지 않는다.

시간·분량 목표는 두지 않는다. 기존 ‘60분 확보’와 1~6장 분량 제한은 적용하지 않는다. 1장부터 원문 순서로 검토한다.

- [x] 1. 제작 기준 고정: 게시 각색문 28장, 원고 원본, 배역표·페르소나, 지침의 파일 해시와 기준 커밋 기록.
- [x] 2. 1장 문장 분할: 18문단을 60문장으로 분리. 문자 범위·문단 복원 일치 확인. 문장별 연기·연속성은 초안이며 미확정.
- [ ] 3. 화자 확인: 원문·앞뒤 문맥 대조. 불명확하면 사용자 검토를 받고 확정 전 생성 보류.
- [ ] 4. 문장별 페르소나 적용과 연기 설계: 근거가 되는 행동 묘사 연결, 문단의 분위기 유지.
- [ ] 5. 화자·연기 근거·연속성의 별도 반복 검수.
- [ ] 6. 검토 완료 대본으로 HTML 제작 및 문장별 시험 생성·문단 순서 청취.
- [ ] 7. 확인된 기준으로 다음 장 순차 확대.

## 필수 납품 · HTML 코드 복사 웹페이지와 공개 배포

참조: https://kingspledu.github.io/tiger-reading-viewer/tts/ (2026-11-23 실제 HTML 확인).

- [ ] 검토가 끝난 문장별 대본으로 최신 스킬의 공통 렌더러를 통해 Canvas HTML 생성.
- [ ] 파우스트 `/tts/` 경로에 코드 복사 웹페이지 제작. 복사하는 것은 URL이나 대본만이 아니라 실행 가능한 HTML 전체다.
- [ ] 참조 페이지처럼 실제 HTML을 불러와 파일 크기·SHA-256 검증 후 복사 활성화. 실패 시 이전 코드나 오류 페이지를 복사하지 않음.
- [ ] 사용자의 기존 요청대로 배역별로 HTML을 쪼개지 않음. 본편은 장별 제작 단위를 유지하되, 한 장의 모든 문장·배역은 하나의 HTML에 포함. HTML 안의 음성 생성은 반드시 한 문장씩 독립 요청·독립 파일.
- [ ] 생성 코드 전달 UI는 복사 버튼 중심. 자동 복사 차단 시 전체 코드 선택으로 수동 복사 제공. 별도 HTML 다운로드 버튼은 기존 사용자 요청에 따라 두지 않음.
- [ ] 미검토·화자 확인 대기인 장은 준비 중으로 표시하고 생성 가능한 코드로 제공하지 않음. 이전 문단형 HTML을 새 문장형인 것처럼 연결하지 않음.
- [ ] 실제 브라우저 클립보드 내용 일치·404/해시 오류 거부·빠른 선택 전환·모바일 표시 검사.
- [ ] manifest와 실제 HTML들을 함께 GitHub Pages에 배포하고 배포 커밋·공개 파일 해시 확인.
- [ ] 코드 복사·배포 검증과 Canvas 실제 음성 생성·다운로드·청취 검증을 따로 보고.

첫 공개 대상은 문장별 검토를 통과한 1장이다. 이후 완성한 장을 같은 페이지에 순차 추가한다. 이 항목은 계획 확정이며 아직 새 본편 코드 복사 페이지의 제작·배포 완료를 뜻하지 않는다.

## 기준 자료

`baseline.json`은 파일 해시·성우·페르소나·기준 커밋을 기록한다. `published-prose.snapshot.json`은 게시된 한국어 각색문을 문단 순서로 추출한 작업용 사본이다. 원문·번역 접기는 낭독하지 않는다.

이 기록은 현재 입력을 고정한 것이며, 기존 화자 표시가 정확하다고 승인하거나 문장별 검토를 완료했다는 뜻이 아니다. 기존 1,853개 TTS 구간과 HTML은 문단형 이전 산출물로, 새 문장별 제작에 바로 사용하지 않는다.

후속 원고·성우·페르소나·지침 변경은 파일 지문으로 탐지하고 변경 문장의 화자·연기를 다시 검토한다. 미확정 내용을 자동 confirmed로 바꾸지 않는다. 기준 파일은 자동 빌드 과정에서 다시 덮어쓰지 않으며, 새 기준을 만들 때 명시적으로 revision을 올린다.
